# Enerifc 要件定義（MVP）

最終更新: 2026-08-23  
状態: 初稿（実装前）。未決事項は [decisions.md](./decisions.md) を参照。

## 1. プロダクト概要

**Enerifc** は、非住宅建築物の BIM モデル（IFC）から、建築物省エネ法の **モデル建物法** 入力（様式 A / B）を組み立て、**BPIm** と **BEIm** を算出する Web アプリです。

キャッチコピー（ランディング）:

- BIMデータで変わる省エネ計算
- BIMモデルを読み込むだけで自動化
- 非住宅向け簡易省エネ計算サービス（モデル建物法）

価値（UI 上の 3 点）:

1. 手入力の手間・ミス・工数を減らす
2. プラン変更後にすぐ再計算できる
3. 専門知識がなくても計算まで辿れる

### 1.1 MVP の計算方針（1 行）

設備の様式 **C〜I は送らない**。BEIm は、建物用途から決まる **国定モデル建物** の設備前提で、モデル建物法プログラムが返す値を使う。

```
IFC アップロード
  → 様式 A（基本情報）/ B1（開口部）/ B2（断熱）/ B3（外皮）を案件に保存
  → 「新規計算」で計算結果行を作成
  → モデル建物法 API を実行
  → BPIm / BEIm / PAL* 等を同じ行に保存
```

対象プログラム版: **Ver.3.10**（`master_program_versions.version = '3.10'`）。

## 2. 背景と対象ユーザー

| 項目 | 内容 |
|------|------|
| 対象建物 | 非住宅（事務所等）。住宅の外皮計算は対象外 |
| 想定ユーザー | 意匠・設備の設計者。省エネ計算の専門家でなくても使えること |
| 計算根拠 | モデル建物法入力シート Ver.3.10 と、そのプログラム／API |
| 学習目的 | 実装者自身がコードを理解しながら作る。詳細は [development-guide.md](./development-guide.md) |

## 3. スコープ

### 3.1 MVP に含む

- メール／パスワードによる会員登録・ログイン・ログアウト・パスワード再設定
- アカウント（氏名・会社名）の表示と更新
- お問い合わせの送信
- プロジェクト（建物案件）の作成・一覧・検索・ステータス絞り込み・論理削除
- IFC（`.ifc`）のアップロードと解析ジョブの記録
- IFC からの数量抽出（床面積・開口部・外皮）と、画面での確認・手修正
- 様式 A / B1 / B2 / B3 の保存（案件単位で共有）
- 計算結果の複数保存（1 案件に複数レポート）
- 計算結果一覧（BPIm / BEIm / 基準適合）と個別レポート（PAL* 含む）
- 個別レポートの印刷プレビュー・PDF ダウンロード（UI 上の機能。実装時期はフェーズ後半）
- 3D プレビュー（That Open Engine）。基本情報・開口・断熱・外皮の作業画面

### 3.2 MVP に含まない

- 様式 C〜I（空調・換気・照明・給湯・昇降機・太陽光・コージェネ）の入力と送信
- 設備ごとの評価範囲マスタ
- 自前のユーザー／セッション／パスワードハッシュテーブル（Supabase Auth に委譲）
- マルチユーザー共同編集、組織内権限（案件は作成者のみ）
- モバイル専用 UI（まずはデスクトップ。Figma もデスクトップ前提）
- 自治体マスタ（都道府県・市町村）からの地域区分自動判定。地域はプルダウンで選ぶ
- ZEB ランク（ZEB Ready 等）の公式判定ロジック ※UI モックにはあるが DB 未定義。扱い未決

## 4. ユーザーストーリー（MVP）

1. 未ログインの人として、トップからサービスの説明を見て登録できる。
2. 会員として、メールとパスワードでログイン・ログアウトできる。
3. 会員として、氏名と会社名をアカウント設定で更新できる。メールは認証情報として扱う。
4. 会員として、プロジェクトを名前付きで作り、IFC をアップロードして解析を開始できる。
5. 会員として、3D を見ながら基本情報・開口部・断熱・外皮を確認し、必要なら手で直せる。
6. 会員として、確認済みの入力から計算を実行し、BPIm / BEIm の適合を一覧とレポートで見られる。
7. 会員として、同じ案件で入力を変えて複数回計算し、レポートを比較できる。
8. 会員として、不要なプロジェクトや計算結果を削除できる（確認ダイアログあり）。
9. 会員として、問い合わせを送れる。

## 5. 機能要件

### 5.1 認証・アカウント

| ID | 要件 | 備考 |
|----|------|------|
| AUTH-01 | 新規登録: 氏名・メール・パスワード（8 文字以上） | `signUp` 後に `profiles.display_name` を保存 |
| AUTH-02 | ログイン: メール・パスワード | |
| AUTH-03 | パスワード再設定: 登録メールへリンク送信 | Supabase Auth のリセットフロー |
| AUTH-04 | ログアウト（確認モーダル） | |
| AUTH-05 | アカウント設定: 氏名（必須）・会社名・メール表示 | メール変更は MVP では必須にしない（表示中心） |
| AUTH-06 | サイドバーに表示名・会社名・頭文字アバター | `profiles` + `companies` |

サインアップ時、`auth.users` INSERT をトリガーに `profiles` を自動作成する（計画 SQL の `handle_new_user`）。

### 5.2 プロジェクト

| ID | 要件 | 備考 |
|----|------|------|
| PRJ-01 | 一覧: 名前・更新日・ステータス・延床面積 | 検索・ステータス絞り込み |
| PRJ-02 | 新規: プロジェクト名 + IFC アップロード | 解析開始で `ifc_extracting` |
| PRJ-03 | 論理削除（確認モーダル。「取り消せない」） | `deleted_at` |
| PRJ-04 | 案件ステータス | `draft` / `ifc_extracting` / `review` / `calculating` / `completed` / `failed` |

UI モックの「ZEB判定」列は DB に無い。MVP では出さないか、計算結果から後付けするかは未決（DEC-03）。

### 5.3 IFC と抽出

| ID | 要件 | 備考 |
|----|------|------|
| IFC-01 | `.ifc` を案件に紐づけて保存 | Storage パスを `project_ifc_files.file_path` に記録 |
| IFC-02 | 抽出ジョブを記録 | `pending` → `running` → `completed` / `failed` |
| IFC-03 | 床面積・開口・外皮を抽出して保存 | `data_source = ifc_auto`、`ifc_global_id` を可能な範囲で保持 |
| IFC-04 | ユーザー確認フラグ | 各入力行の `is_confirmed` |
| IFC-05 | 手修正可能 | `data_source = manual` に切り替えられること |
| IFC-06 | 3D プレビュー | Show All / Ghost / Focus / Hide / Isolate / Colorize |

抽出の詳細ルール（どの IFC クラスを床・壁・窓とみなすか）は、バックエンドの抽出設計時にサンプルモデルで決める。ここでは「様式 A/B を埋めるのに足る数量を取る」ことを要件とする。

### 5.4 様式入力（案件単位、計算結果とは 1:N）

入力は **プロジェクトに 1 セット**。計算のたびに結果行だけ増える。

#### 様式 A（基本情報）— `project_basic_info`

- 建物名称
- 建設地（地域区分）← `master_region_categories`
- 建物用途 ← `master_building_uses`（ここから国定モデル建物が決まる）
- 延床面積（m²）。階別内訳は `project_floor_areas`

UI モックの「主たる空調方式」は様式 C 相当のため **MVP では持たない**（DEC-04）。

#### 様式 B1（開口部）— `project_openings`

- 符号、建具、ガラス、寸法、開口面積、ガラス面積、方位、U 値、日射熱取得率、個数
- 入力方法: 建具+ガラス / 建具+ガラス性能 / 窓性能

#### 様式 B2（断熱仕様）— `project_insulation_specs`

- 仕様名、部位、入力方法、断熱材種類、厚み、熱伝導率、U 値

#### 様式 B3（外皮面積）— `project_envelope_areas`

- 部位 × 方位ごとの外皮面積・開口面積、断熱仕様との紐づけ

### 5.5 計算結果

| ID | 要件 | 画面 |
|----|------|------|
| CALC-01 | 1 案件に複数レポート。`(project_id, report_name)` 一意 | 一覧 |
| CALC-02 | ステータス: `draft` / `calculating` / `completed` / `failed` | 一覧 |
| CALC-03 | BPIm, BEIm, それぞれの基準適合、基準上限（既定 1.0） | 一覧・個別 |
| CALC-04 | 総合判定 `overall_goal_status`（目標達成 / 未達成） | 個別 |
| CALC-05 | PAL* 設計値、年間熱負荷（設計／基準）、ペリメーターゾーン面積 | 個別 |
| CALC-06 | BEIm 注記（国定モデル建物の説明文） | 個別 |
| CALC-07 | API の生レスポンスを `model_building_api_runs` に保存 | 内部 |

設備シートを送らないため、BEIm は「用途 → モデル建物」の前提である旨をレポートに出す。

### 5.6 その他

| ID | 要件 |
|----|------|
| CTL-01 | お問い合わせ: 氏名・会社名・メール・本文。ログインユーザーなら `user_id` を付与 |
| CTL-02 | 未ログインでもトップと問い合わせ、認証画面には入れる |

## 6. 画面要件

画面一覧・URL・アクセス権は [sitemap.md](./sitemap.md)。見た目の正は `enerifc_DB_plannning/figma_UIdesign/`。

共通:

- 認証系は中央カード。ログイン後は左サイドバー
- 案件ワークスペースは **左ナビ / 中央 3D / 右データパネル** の 3 ペイン（結果一覧・レポートは 3D なし）

## 7. データ要件

詳細は [database.md](./database.md)。要点だけ:

- 認証: Supabase Auth（`auth.users`）
- 業務データ: `public` スキーマ。Prisma で管理
- マスタ: 入力シート Ver.3.10 の `data` シート等から seed。[master-data.md](./master-data.md)
- ファイル: IFC はオブジェクトストレージ（Supabase Storage 予定）
- 権限: 案件とその子は作成者のみ。マスタは認証済み読み取り

## 8. 外部連携

| 連携先 | 用途 | MVP |
|--------|------|-----|
| Supabase Auth / Postgres / Storage | 認証・DB・IFC 保管 | 必須 |
| モデル建物法プログラム API | BPIm / BEIm / PAL* | 必須。エンドポイント・認証は未決（DEC-05） |
| That Open Engine | IFC 読み込み・Fragments 化・3D・プロパティ参照 | 必須。3D はブラウザ。抽出をサーバでやるかは DEC-06 |

## 9. 非機能要件

| 項目 | 目標（MVP） |
|------|-------------|
| 言語 | UI は日本語。コード・コミットは英語でも可。docs は日本語 |
| ブラウザ | デスクトップ Chrome 最新相当。WebGL / WASM 必須（3D） |
| 学習コスト | 1 機能ずつ理解できる大きさ。レビュー 1000 行以内 |
| セキュリティ | パスワードは自前保存しない。RLS または同等のサーバ側所有者チェック |
| 監査 | API 生レスポンスを残し、画面値はパース結果として再現できること |
| 版管理 | マスタは `program_version` で切る。MVP は 3.10 のみ active |

## 10. 成功条件（MVP 受け入れ）

1. サンプル IFC を上げ、様式 A/B が画面に現れ、手修正できる
2. 計算実行後、一覧に BPIm / BEIm と適合が出る
3. 個別レポートに総合判定と PAL* 系が出る
4. 別ユーザーの案件は見えない
5. マスタの地域・用途・建具・ガラス・断熱・方位・部位が Ver.3.10 シート由来である

## 11. 用語

| 用語 | 意味 |
|------|------|
| 様式 A | 基本情報（建物名称、地域、用途、延床） |
| 様式 B1/B2/B3 | 開口部 / 断熱仕様 / 外皮面積 |
| 様式 C〜I | 設備。MVP では入力・送信しない |
| BPIm | モデル建物法の外皮性能指標（基準 1.0 以下で適合、モック表示） |
| BEIm | モデル建物法の一次エネルギー指標（国定モデル建物前提） |
| PAL* | 外皮の年間熱負荷指標 |
| 国定モデル建物 | 用途に紐づく標準設備前提。`master_model_buildings` |
| Fragments | That Open が IFC を変換した表示用バイナリ |
