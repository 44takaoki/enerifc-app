# マスタデータ（入力シート Ver.3.10）

最終更新: 2026-08-23  
原典: `enerifc_DB_plannning/sample_MODEL_inputSheet_for_Ver3.10.xlsx`

マスタは基本的にこのブックから抽出する。手入力で「それっぽい」選択肢を増やさない。シートに無い表示名が UI で必要なときだけ、変換ルールをこの文書に書く。

## 1. ブック構成

| シート | MVP |
|--------|-----|
| 地域の区分および年間の日射地域区分 | 使わない（市区町村→地域の自動判定は対象外） |
| 様式A_基本情報 | 列の意味の参照。行データは案件 |
| 様式B1_開口部仕様 / B2_断熱仕様 / B3_外皮 | 同上 |
| 様式C1〜I | **送らない。** マスタ化もしない |
| `data`（非表示） | **マスタの主原典** |
| 入力エラー / QC | 使わない |

`data` の名前付き範囲（Defined Names）が、プルダウンの正である。

## 2. `data` 列 → テーブル

| 列 | 名前 | 行数目安 | Prisma テーブル | MVP |
|----|------|----------|-----------------|-----|
| A | RegionList | 8 | `master_region_categories` | 使う |
| B | RegionForPhotovoltaicGenerationList | 5 | — | 使わない（様式 H） |

| D | DirectionList | 5 | `master_orientations` の一部 | 開口の方位 |
| E | WindowTypeList | 14 | `master_frame_types` | 使う |

`master_program_versions` の初期行: `3.10` / 「モデル建物法 Ver.3.10」。

`master_model_buildings` は `data` に 1 列では無い。様式 A の名前付き範囲（事務所モデル、ホテルモデル等）と、用途との対応を seed で持つ。対応表は seed 実装時にシートを見てこの節へ追記する。

## 3. 抽出値（確認用）

seed のテストに使う。完全な 156 ガラス符号は seed ファイルを正とする。

**地域（A）:** 1地域 … 8地域

**建物用途（C）:**  
事務所モデル / ビジネスホテルモデル / シティホテルモデル / 総合病院モデル / 福祉施設モデル / クリニックモデル / 学校モデル / 幼稚園モデル / 大学モデル / 講堂モデル / 大規模物販モデル / 小規模物販モデル / 飲食店モデル / 集会所モデル / 工場モデル

**開口方位（D）:** 北 / 東 / 南 / 西 / なし

**建具（E）:** 樹脂・木・金属樹脂複合・金属木複合・金属 × 単板 / 二層 / 三層（金属は「二層以上」）

**外皮部位（G）:** 外壁 / 屋根 / 外気に接する床

**断熱材大分類（H）:**  
グラスウール断熱材通常品 / 高性能品 / 吹込み用グラスウール / ロックウール / 吹込み用ロックウール / 吹付けロックウール / 吹込み用セルローズファイバー / 押出法ポリスチレンフォーム / ポリエチレンフォーム / ビーズ法ポリスチレンフォーム / 硬質ウレタンフォーム / 吹付け硬質ウレタンフォーム / フェノールフォーム / インシュレーションファイバー

**外皮方位（J）:** 北 / 東 / 西 / 南 / 屋根 / 床

**断熱の入力方法（Y）:**

1. 断熱材の種類(大分類のみ)と厚みを入力する
2. 断熱材の種類と厚みを入力する
3. 熱伝導率と厚みを入力する
4. 熱貫流率を入力する
5. 入力しない

`method_code` は seed 時に `A`〜`E` など 1 文字で振る（シートにコード列が無いため。振り方を決めたらここに固定する）。

**ガラス（F）:** `3WgG06` 形式の符号。`display_name` は当面 `sheet_value` と同じでよい。説明文がシート他列にあれば後で足す。

## 4. 方位マスタの統合

開口は「なし」、外皮は「屋根」「床」がある。**`master_orientations` はユニオン**する。

`sheet_value` 例: 北, 東, 南, 西, なし, 屋根, 床  
画面では開口ドロップダウンから「屋根」「床」を外す、外皮から「なし」を外す、といった **API クエリ側のフィルタ**で対応する。

## 5. seed の作り方

1. ブックをリポジトリにコピーしない（大きいバイナリ）。`enerifc_DB_plannning` を読み取り専用原典にする。
2. 抽出スクリプト（Node）で JSON または `prisma/seed.ts` 用モジュールを生成する。
3. 生成物は git 管理し、シート更新時はスクリプト再実行。
4. スクリプトと生成物は **別レビュー** に分けて 1000 行を超えないようにする（ガラス 156 行は分割可）。

C〜I 用リストは生成しない。
