### 用途とモデル建物の対応（Ver.3.10）

様式 A の「モデル建物法で適用する建物モデルの種類（建物用途）」は、`data` 列 C（BuildingTypeNameList）の **15 件** を選ぶ。値が `事務所モデル` のようにモデル名そのものなので、MVP の **seed は用途 1 件 = モデル建物 1 件** とする。

テーブルはもともと **用途 N : モデル 1**（`model_building_id` に一意制約は無い）。あとから「事務所等」など用途行を足して同じモデルを指すことは、スキーマ変更なしでできる。1 用途が複数モデルを指す形にするときだけ、中間テーブルが必要になる。

**断熱の入力方法（Y）:**

1. 断熱材の種類(大分類のみ)と厚みを入力する

**ガラス（F）:** `3WgG06` 形式の符号。`display_name` は当面 `sheet_value` と同じでよい。説明文がシート他列にあれば後で足す。

## 4. 方位マスタの統合

開口は「なし」、外皮は「屋根」「床」がある。**`master_orientations` はユニオン**する。

`sheet_value` 例: 北, 東, 南, 西, なし, 屋根, 床  
画面では開口ドロップダウンから「屋根」「床」を外す、外皮から「なし」を外す、といった **API クエリ側のフィルタ**で対応する。

## 5. seed の作り方

1. ブックをリポジトリにコピーしない（大きいバイナリ）。`enerifc_DB_plannning` を読み取り専用原典にする。
2. 抽出結果は `prisma/seed/data/v3.10/*.json` に置く。投入は `prisma/seed.ts`（`npm run db:seed`）。
3. JSON は git 管理する。シート更新時は JSON を差し替えて seed を再実行する。
4. Phase B は一括レビュー（DEC-16）。ガラス 156 行は JSON をコンパクトに保つ。

C〜I 用リストは生成しない。
